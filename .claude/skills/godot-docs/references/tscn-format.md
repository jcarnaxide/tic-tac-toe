# The .tscn Scene File Format

For reading and hand-writing Godot scene files. Everything marked **[verified]**
was round-tripped through Godot 4.7.1 - either generated by the engine itself or
hand-written and confirmed to load.

## Anatomy

A `.tscn` is an INI-like text file of bracketed sections, read top to bottom.
Order matters: a resource must be declared before the node that references it.

```
[gd_scene format=3]

[ext_resource type="Script" path="res://cell.gd" id="1_qjl83"]

[sub_resource type="StyleBoxFlat" id="StyleBoxFlat_of00a"]
bg_color = Color(0.2, 0.2, 0.25, 1)

[node name="Main" type="Control"]
layout_mode = 3

[node name="Board" type="GridContainer" parent="."]
columns = 3
```

`.tres` files use the same syntax with a `[gd_resource ...]` header, for
standalone resources rather than scenes.

## The header

```
[gd_scene format=3]
[gd_scene load_steps=4 format=3 uid="uid://bx8vn2p4kqm1r"]
```

`format=3` is Godot 4. Both other fields are **optional [verified]** - a
hand-written scene with neither loads fine:

- **`load_steps`** is a loading-progress hint, not a checksum. Godot 4.7 omits it
  entirely when saving. You do not need to count resources to get it "right",
  and a wrong value is not fatal.
- **`uid`** is a stable identifier letting other files reference this scene even
  if it moves. The editor assigns one on save; omit it when hand-writing and
  Godot will add one when it next saves the file.

## ext_resource

External files this scene depends on - scripts, textures, other scenes.

```
[ext_resource type="Script" path="res://scripts/cell.gd" id="1_qjl83"]
[ext_resource type="PackedScene" path="res://scenes/cell.tscn" id="2_a1b2c"]
[ext_resource type="Texture2D" path="res://icon.svg" id="3_x9y8z"]
```

The `id` is an arbitrary string, unique within the file. Godot generates
`<number>_<random>` but any unique string works. Reference it as
`ExtResource("1_qjl83")`.

## sub_resource

Resources that live inside this scene rather than in their own file.

```
[sub_resource type="StyleBoxFlat" id="StyleBoxFlat_of00a"]
bg_color = Color(0.2, 0.2, 0.25, 1)

[sub_resource type="RectangleShape2D" id="RectangleShape2D_m3n4o"]
size = Vector2(96, 96)
```

Referenced as `SubResource("StyleBoxFlat_of00a")`. Properties follow on
subsequent lines until the next `[section]`.

Declaring one sub-resource and referencing it from several nodes genuinely
shares it - duplicating the block instead creates independent copies, which is a
common source of "why did styling one button change all of them" (or fail to).

## node

```
[node name="Main" type="Control"]
[node name="Board" type="GridContainer" parent="."]
[node name="Cell0" type="Button" parent="Layout/Board"]
[node name="Enemy" parent="." instance=ExtResource("2_a1b2c")]
```

- The **first** `[node]` with no `parent` is the root.
- `parent="."` means a direct child of the root.
- `parent="Layout/Board"` is a path **relative to the root**, using node names.
- `instance=ExtResource(...)` instantiates another scene instead of `type=`.
- `unique_id=` appears in 4.7-saved files and is **optional when
  hand-writing [verified]**.
- Add `unique_name_in_owner=true` to reach the node as `%Name` from script.

Properties are written as `property = value` on the lines after the header, and
**only serialize when they differ from the default**. A scene file is a diff
against defaults, not a full dump - so absence means "default", not "unset".

## Property value syntax

```gdscript
text = "X to move"                      # String
columns = 3                             # int
visible = false                         # bool
custom_minimum_size = Vector2(96, 96)   # Vector2
bg_color = Color(0.2, 0.2, 0.25, 1)     # Color, RGBA 0..1
position = Vector2(10, 20)
metadata/my_key = "value"               # arbitrary metadata
script = ExtResource("1_qjl83")
theme_override_styles/normal = SubResource("StyleBoxFlat_of00a")
theme_override_colors/font_color = Color(1, 1, 1, 1)
theme_override_font_sizes/font_size = 24
```

Nested properties use a slash: `theme_override_styles/normal`,
`metadata/author`. Colors are floats 0..1, not 0..255.

## Control nodes and layout_mode

`layout_mode` decides which positioning fields apply, and getting it wrong is
the most common reason a hand-written UI renders in the wrong place:

- **`layout_mode = 0`** - position/size set directly.
- **`layout_mode = 2`** - the node is inside a container, which owns its
  position. Use this for anything under a `VBoxContainer`, `GridContainer`, etc.
- **`layout_mode = 3`** - anchored to its parent's rect. Pair with
  `anchors_preset` and the `anchor_*` fields.

A full-rect root looks like **[verified]**:

```
[node name="Main" type="Control"]
layout_mode = 3
anchors_preset = 15
anchor_right = 1.0
anchor_bottom = 1.0
```

Children of a container should use `layout_mode = 2` and control their size with
`custom_minimum_size` and `size_flags_horizontal` / `size_flags_vertical` -
setting `position` on them does nothing, because the container overwrites it.

## Signal connections

```
[connection signal="pressed" from="Board/Cell0" to="." method="_on_cell_pressed"]
[connection signal="pressed" from="Board/Cell1" to="." method="_on_cell_pressed" binds= [1]]
```

Placed after all `[node]` sections. Paths are relative to the root, `to="."`
being the root itself. `binds=` appends extra arguments to the handler.

Editor-made connections live here; script-made ones (`connect()` in `_ready()`)
do not appear in the file at all. For anything generated in a loop, connecting
from script is usually clearer than writing N connection lines.

## Minimum viable scene

This is the whole thing - it loads and runs **[verified]**:

```
[gd_scene format=3]

[ext_resource type="Script" path="res://probe.gd" id="1_probe"]

[node name="Main" type="Control"]
layout_mode = 3
anchors_preset = 15
anchor_right = 1.0
anchor_bottom = 1.0
script = ExtResource("1_probe")

[node name="Board" type="GridContainer" parent="."]
layout_mode = 2
columns = 3

[node name="Cell0" type="Button" parent="Board"]
custom_minimum_size = Vector2(96, 96)
layout_mode = 2
text = "1"
```

## Pitfalls

**Resources must precede their references.** All `[ext_resource]` and
`[sub_resource]` blocks go above the `[node]` blocks that use them.

**Parent paths use node names, not types.** `parent="Layout/Board"` breaks the
moment either node is renamed, and the failure is a load error, not a warning.

**Every `ExtResource`/`SubResource` id must resolve.** A reference to an id that
was never declared fails the scene load outright.

**Prefer generating repetitive nodes from script.** Nine near-identical button
blocks are nine chances to typo a parent path. Declaring the container in the
scene and populating it in `_ready()` is shorter and safer.

**Always verify after hand-writing.** `godot-verify smoke` loads the scene for
real and reports what broke - a malformed scene is not something `check` can
catch, since that only parses GDScript.
